## 原始叙述
> 此模块吸收旧设计中的 LAB-03（用户可编程沙箱），从原「教学实验套件」中独立拆分。
>
> 拆分理由：可编程沙箱是整个作品中工程复杂度最高的功能（Pyodide + CodeMirror 6 + 安全沙箱），使用场景独立（"从使用给定模型到创造新模型"），依赖链路也独立（不依赖受力拆解和物理验证）。独立成模块后可以不受其他教学功能的工期影响，按 P3 优先级在最末尾决策是否实现。
>
> **旧设计原文摘录**（功能设计_v0.md）：
> - LAB-03: 提供浏览器内 Python 代码编辑器，允许用户修改运动方程并即时生效。Python 语法高亮编辑器；白名单 import（numpy + 标准库子集）；执行超时 5s；报错时行号高亮 + 中文错误翻译；3 个预设模板（弹簧摆/受迫摆/磁力摆）；修改代码运行后 3D 场景立即切换至新模型。

## AI 提炼摘要
### 功能定位
将双摆非线性动力学虚拟仿真实验从"使用给定模型"升级为"创造物理模型"——提供一个浏览器内 Python 代码编辑器，用户可修改运动方程，运行后 3D 场景立即切换至新模型。这是作品工程能力的最高展示。

### 目标用户
- 学生（本科物理/工科高年级）：修改运动方程实验"如果弹簧连接会怎样""如果加驱动力会怎样"
- 教师：现场演示"修改一行代码，物理系统完全改变"，展示数值仿真的灵活性
- 评委：浏览器内 Python 沙箱 + 3D 场景联动，展示纯前端工程的边界

### 核心场景
1. **基于模板实验**：学生打开代码编辑器 → 选择"弹簧摆"预设模板 → 看到连接两摆的杆被替换为弹簧的 Python 代码 → 修改弹簧劲度系数 k=100 → 点击"运行" → 3D 场景从刚性双摆切换为弹簧连接的双摆 → 观察弹簧刚度如何影响混沌行为
2. **从零编写模型**：学生清空编辑器 → 参考文档（numpy + SciPy solve_ivp）编写自己的运动方程 → 点击运行 → 代码报错 IndexError → 编辑器行号高亮 + 右侧显示"数组越界，请检查维度" → 修正后重新运行 → 3D 场景渲染学生自定义模型
3. **交叉验证**：教师先用标准双摆做一个实验 → 再切换到沙箱用 Python 重写同一组运动方程 → 对比两种实现的结果是否一致（交叉验证物理引擎）

### 关键功能点
- **Python 代码编辑器**（CodeMirror 6）：Python 语法高亮、行号显示、缩进辅助；3 个预设模板一键加载——弹簧摆（杆替换为弹簧）、受迫摆（加入周期性驱动力）、磁力摆（加入磁场洛伦兹力项）
- **安全沙箱**（Pyodide）：白名单 import——numpy + 标准库子集（math、json 等）；执行超时 5 秒强制中断；禁止文件系统访问、禁止网络请求
- **错误友好反馈**：代码执行报错时编辑器行号高亮 + 右侧面板显示中文错误翻译（如 IndexError→"数组越界，请检查维度"、TypeError→"类型错误，请检查输入参数类型"）
- **即时模型切换**：用户代码运行成功 → 轨迹数组通过 JsProxy 转换为 Float64Array → 注入 3D 场景 → 当前视角、参数面板保留，仅摆的运动模型切换

### 边界与约束
- P3 优先级——视工期决定是否实现，是所有功能模块中最后考虑的一项
- 安全边界不可妥协：白名单 import、5s 超时、禁止文件系统和网络——即使沙箱被"突破"也不影响宿主页面
- 不提供 Python 调试器（无断点/单步执行），错误反馈仅限于行号高亮 + 中文翻译
- 用户自定义模型的物理正确性不在「物理验证套件」的覆盖范围内
- 移动端禁用（手机屏幕不适合代码编辑 + Pyodide 内存开销大）

### 依赖项
- 仿真引擎与3D场景（3D 场景响应模型切换）
- 参数面板与模式导航（实验模式页面入口）
- Pyodide 运行时（浏览器内 Python 执行环境）
- CodeMirror 6（代码编辑器组件）
