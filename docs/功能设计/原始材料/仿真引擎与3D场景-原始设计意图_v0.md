## 原始叙述
> 此模块吸收旧设计中的 SIM-01（双摆物理引擎）、SIM-04（能量实时监控）、SIM-05（相空间可视化）、EXP-01（3D仿真场景）、EXP-02（运动尾迹渲染）五个模块。
>
> 合并理由：物理引擎是系统最底层的计算核心，能量监控和相空间可视化是其直接派生的一维/二维数据可视化面板，3D场景和尾迹渲染共享同一个 R3F Canvas，五者在运行时不可分割——物理计算输出驱动所有可视化，可视化在同一帧内同步更新。拆分为五个"独立模块"导致接口碎片化和测试困难。
>
> **旧设计原文摘录**（功能设计_v0.md）：
> - SIM-01: 对双摆耦合 ODE 系统执行实时数值积分，驱动所有模式下的仿真时间推进。支持可配置积分步长；仿真刷新率 ≥ 60 FPS；含阻尼项；输出完整状态向量 (θ₁, θ̇₁, θ₂, θ̇₂) 供下游模块消费。
> - SIM-04: 实时追踪系统动能与势能总和，检测能量漂移。1000s 仿真内漂移 < 0.5% 视为通过守恒检验；超阈值时自动提示。
> - SIM-05: 在 2D 相平面中实时绘制系统状态轨迹。支持 θ-θ̇ 相平面绘制；可切换状态变量对（θ₁-θ̇₁ 或 θ₂-θ̇₂）。
> - EXP-01: 实时渲染双摆运动的 3D 视觉场景。3 种预设视角（实验员侧视/上帝俯视/混沌跟随）+ 自由旋转缩放；3 种摆体材质视觉（金属/木质/玻璃）；2 种环境背景（暗室聚光/纯白教学）。
> - EXP-02: 速度-颜色映射尾迹（静止蓝 → 高速红）；尾迹粗细随速度变化；5 种持久度；暂停时尾迹定格支持 360° 旋转观察。

## AI 提炼摘要
### 功能定位
双摆混沌实验室的存在基石——为全部四种工作模式提供实时物理仿真计算、3D视觉渲染、运动尾迹可视化和实时物理量（能量、相空间）反馈。没有此模块，产品不存在。

### 目标用户
- 公众/参观者：通过3D场景和彩色尾迹建立对混沌运动的直觉认知
- 学生（本科物理/工科）：观察能量守恒曲线和相空间轨迹，理解动力学系统的状态空间表示
- 教师：利用可配置的积分方法（RKF45/VelocityVerlet/Euler）进行数值方法教学对比
- 评委：3D场景的视觉冲击力是评审现场的第一印象

### 核心场景
1. **启动即见运动**：用户打开应用 → 3D场景中双摆正在运动 → 彩色尾迹描绘运动轨迹 → 旋转/缩放观察空间几何结构 → 能量曲线和相空间图在侧面板实时更新
2. **参数驱动的视觉反馈**：用户在参数面板调节质量/摆长/初值 → 3D场景中摆体大小/摆杆长度即时响应 → 运动模式随之改变（周期→准周期→混沌）→ 能量曲线形态变化、相空间轨迹从闭合曲线变为填充区域
3. **暂停观察与教学定格**：用户暂停仿真 → 尾迹冻结在3D空间 → 360°旋转从任意角度观察运动的空间包络 → 能量图上显示当前时刻标记线 → 相空间图上高亮当前状态点

### 关键功能点
- **ODE数值积分引擎**：支持 RKF45（默认自适应）、VelocityVerlet、Euler 三种积分方法；仿真刷新率 ≥ 60 FPS；含阻尼项；输出完整状态向量 (θ₁, θ̇₁, θ₂, θ̇₂, x₁, y₁, x₂, y₂, K, V, T)
- **Web Worker 批量积分**：主线程与计算线程隔离；Float64Array Transferable 池（10×4000，约320KB）；RingBuffer<StateVector> 容量 6000（=100s @60fps）
- **3D 场景渲染**（R3F + Three.js）：3 种预设视角（实验员侧视 / 上帝俯视 / 混沌跟随）+ 自由旋转缩放；3 种摆体材质（金属 / 木质 / 玻璃）；2 种环境背景（暗室聚光 / 纯白教学）；摆球大小与质量正相关、摆杆粗细与刚度相关
- **运动尾迹系统**：速度-颜色映射（静止蓝 → 高速红）；尾迹粗细随速度变化；5 种持久度（50步 / 200步 / 1000步 / 无限 / 仅当前周期）；暂停时尾迹定格支持360°旋转观察
- **能量实时监控**：Canvas 2D 折线图（动能/势能/总能量三线叠绘）；实时漂移百分比计算；1000s 仿真内漂移 < 0.5% 视为通过守恒检验；超阈值自动告警
- **相空间可视化**：Canvas 2D 相平面实时轨迹；可切换状态变量对（θ₁-θ̇₁ / θ₂-θ̇₂）；实时轨迹 + 历史轨迹半透明叠加
- **响应式渲染降级**：桌面完整渲染；平板降低球体分段 + 关闭阴影；手机降至最低分段 + 关闭阴影和尾迹
- **Worker 崩溃恢复**：检测 Worker 崩溃 → 自动重建 Worker 实例 → 恢复最后已知参数和状态 → 最多重试 1 次

### 边界与约束
- **不做 GPU 加速**：所有物理计算在 CPU（Web Worker）中完成，不依赖 WebGPU/WebGL Compute
- **不做物理正确性证明**：本模块提供仿真，物理正确性由「教学实验套件」模块的验证功能背书
- **渲染降级不影响物理**：设备降级仅影响视觉质量（球体分段数、阴影开关），物理积分精度在所有设备上保持一致
- **能量监控仅追踪不修正**：检测到能量漂移超阈值时发出告警提示，不自动调整积分步长或修正能量值
- **尾迹 Buffer 内存上限**：RingBuffer 容量固定 6000 帧，超出后自动覆盖最早帧

### 依赖项
- 无（系统最底层计算与渲染模块，所有其他模块依赖本模块）
