## 四、发现的问题与风险

### 🔴 严重：无

### 🟡 中等

**M1: 反向积分 `_simTime` 边界缺失** — ✅ **已修复 (2026-04-28)**

- **位置**：`ode-worker.ts` `handleStep` 函数
- **修复内容**：在 `_simTime += dt * _direction` 之后添加边界检测：`if (_direction === -1 && _simTime <= 0) { _simTime = 0; writeFrame(...); frame++; break; }`
- **commit**：待提交

**M2: Worker 崩溃恢复缺乏前端 toast 通知** — ✅ **已修复 (2026-04-28)**

- **位置**：`scheduler.ts:239-240`
- **修复内容**：在 `SimulationState` 中新增 `engineEvent: { type: "recovered"; message: string } | null` 字段；崩溃恢复时通过 `setState({ engineEvent: {...} })` 写入，供 UI toast 组件消费
- **影响**：用户感知不到引擎恢复，若恢复期间有短暂卡顿无法理解原因。
- **建议修复**：通过 `useSimulationStore.setState({ engineError: null })` 配合一个 toast 通知标记（或由 SYS-02 运行时异常处理模块消费 engineError 变化来实现通知）。这是跨模块集成点，可与 SYS-02 一并处理。

### 🟢 轻微

**L1: Worker 超时未清理 currentBuffer** — ✅ **已修复 (2026-04-28)**

- **位置**：`scheduler.ts` timeout 回调
- **修复内容**：在 timeout 回调中归还 buffer 前，检查 `this.currentBuffer === slot.buffer`，若引用同一块内存则先置空

**L2: bridge.ts 中的 DEBOUNCE_MS 注释缺失来源** — ✅ **已修复 (2026-04-28)**

- **位置**：`bridge.ts:16`
- **修复内容**：添加注释 `/** 参数更新去抖窗口 ≈ 1 帧 @60fps（1/60 ≈ 16.7ms），合并同一帧内的多次按键输入 */`

**L3: 异常测试 1-6 的完整覆盖**

- `engine.test.ts` 27 个测试集中在纯函数和单元层，缺少 Worker 集成测试、池压力集成测试、崩溃恢复集成测试。
- 这些在 jsdom 环境下较难完全自动化（Worker 创建受限），建议在 E2E 层补充。

### 总体评价

SIM-01 的落地质量很高。Worker 侧 8 个步骤的实现与 v2.1 设计文档逐行对齐，`odeRhs` 的公式使用已修正的分母（`m1+m2-m2·cos²δ`），积分器三种方法均正确实现，Float64 池的 acquire/release 成对使用 WeakMap 保护。主线程调度器的帧循环、80% 预取策略、Worker 崩溃恢复均完整。27 个单元测试覆盖了数学正确性和参数校验，能量守恒验证通过（<0.5% 漂移）。

唯一的实质性代码缺口是反向积分的 `_simTime` 边界（M1），影响 EXP-05 时间反演功能的正确性。其余为集成测试补充和 UI 通知集成，可在后续模块落地时一并处理。
