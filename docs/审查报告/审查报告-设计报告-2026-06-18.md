## 致命缺陷（P0 — 必须修复）

### P0-1. 缺少程序流程图（竞赛硬性要求）

- **位置**：`src/sections/sec03_design.tex` 整体
- **问题**：比赛说明 §2.5 明确要求"资源制作或仿真/模拟程序的**流程图**和涉及的实现技术"。当前文档 §3.6 虽有编号步骤文字描述仿真流程，§3.2 有表格化数据流示意图（fbox + tabular），但**无一幅真正意义上的流程图**（带判断分支、循环箭头的图形化流程）。竞赛评委可能据此扣分。

- **建议**：用 TikZ 绘制一幅正式的仿真主循环流程图，包含：参数初始化 → Worker 批量积分 → Transferable 传输 → 多视图同步 → 预取判断 → 缓冲归还等关键节点和判断分支。放在 §3.6「仿真流程」开头。

### P0-2. 系统主界面截图缺失

- **位置**：`src/sections/sec05_validation.tex` 或 `src/sections/sec03_design.tex`
- **问题**：`figures/output/` 目录下存在 `I01_explore-mode-3d-main-scene.png`（118 KB），但**全文中无任何 `\includegraphics` 引用此图**。设计报告没有展示系统的主界面，评委无法直观看到"这个作品长什么样"，严重影响第一印象。
- **严重性**：设计报告的核心目的是向评委展示作品——缺少系统全貌截图是叙事上的重大遗漏。
- **建议**：将 I01 用于 §3（系统设计）开头或 §5（结果分析）开头，配合图注说明 3D 场景、参数面板、能量曲线等界面要素。

#### P1-2. 分岔图与庞加莱截面无配图

- **位置**：`src/sections/sec05_validation.tex` 第 57–71 行

### 维度二：内容审查

#### P1-3. 能量漂移定义的潜在歧义

- **位置**：`src/sections/sec05_validation.tex` 第 29 行
- **问题**：能量漂移定义为 $\eta = |E_\text{max} - E_\text{min}| / |E(0)|$，但此定义测量的是"波动幅度"而非"漂移趋势"。若 $E(t)$ 在 $E(0)$ 上下对称振荡，$\eta$ 可能很大但无系统性漂移。竞赛评委（物理背景）可能质疑此定义的合理性。
- **建议**：补充说明为何采用此定义而非 $\eta(t) = |E(t)-E(0)|/|E(0)|$ 的时间平均值或最大值。或直接改用后者，与 §2.6（`simulationSlice.ts:365-382`）中描述的逻辑保持一致。

#### P1-4. 未引用 Pyodide、React、Three.js 的文献条目

- **位置**：`src/refs.bib` 第 32–52 行
- **问题**：`.bib` 文件中定义了 `pyodide`、`react`、`threejs` 三个在线文献条目，但正文中从未 `\cite{}`。BibTeX 的 `.blg` 明确显示 "You've used 7 entries"（共 10 条，3 条闲置）。虽然不会造成编译错误，但 `.bib` 应保持干净。
- **建议**：在 §3.4（核心技术栈）表格或正文中添加对这三项关键依赖的引用；或从 `.bib` 中删除未使用的条目。

#### P1-5. 可拓展性分析不够具体

- **位置**：`src/sections/sec05_validation.tex` 与 `src/sections/sec06_discussion.tex`
- **问题**：比赛说明要求分析结果的"可拓展性"，当前仅在 §6（改进思路）中以未来改进计划的形式间接涉及，§5（结果分析）未直接讨论当前结果能自然延伸到哪些物理场景。
- **建议**：在 §5 末尾增加一段"结果的可拓展性"，说明：(1) 当前 ODE 框架已支持弹簧摆/受迫摆/磁力摆的模板化替换；(2) 预计算管线可复用于其他非线性系统的参数空间扫描；(3) Python 沙箱支持学生自行拓展模型。

### 维度三：LaTeX 格式审查

#### P1-6. `enumitem` Negative labelwidth 警告

- **位置**：`src/sections/sec03_design.tex` 第 8 行
- **编译日志**：`Package enumitem Warning: Negative labelwidth. This does not make much sense, on input line 8.`
- **问题**：`description` 环境中 `labelwidth=6em` 过小，无法容纳 "Infrastructure 层"（15 个字符 + 空格），导致 label 溢出并触发负宽度警告。
- **建议**：将 `labelwidth` 从 `6em` 增大到 `9em`，或使用 `leftmargin=*` 自动计算（当前已设置），移除显式 `labelwidth` 参数。

#### P1-7. 表格排版优化

- **位置**：`src/sections/sec03_design.tex` 第 150–178 行（代码归属表格）
- **编译日志**：`Overfull \hbox (83.5433pt too wide)` — 83pt 约等于 2.9 cm，即表格右边界溢出页面 2.9 cm。
- **问题**：代码归属表格的 X 列内容过长（含大量中文 + 英文代码文件名），`tabularx` 无法在页面宽度内断行。
- **建议**：使用 `\small` 缩小字号；将「自主编写」列中的分号分隔改为 `\linebreak` 显式换行；或改为 `itemize` 列表而非表格。

#### P1-8. Underfull hbox 警告（4 处）

- **位置**：
  - `sec03_design.tex` 第 177 行（3 处，代码归属表格）
  - `sec04_usage.tex` 第 59 行（1 处，参数范围表格）
  - `sec07_conclusion.tex` 第 43 行（1 处，运行配置表格）
- **问题**：表格中某些列内容过短，TeX 用不合理的间距拉伸，导致 underfull。虽不造成溢出，但表格列间距不均匀。
- **建议**：检查受影响的 `tabularx` 表格，确保 X 列的宽度分配合理。对于参数表，第一列（中文参数名）可手动设置 `p{5em}` 宽度。

## 次要问题（P2 — 建议优化）

### P2-1. 编译警告 `No \author given`

- **位置**：`src/main.tex`（编译日志第 118 行）
- **问题**：为满足匿名性要求，有意未设 `\author{}`，但 LaTeX 会输出 `No \author given` 警告。虽是预期行为，但不够优雅。
- **建议**：`\author{}` 不会在 PDF 中产生可见输出，建议显式设为空以消除警告。

### P2-2. 摘要缺少量化数据

- **位置**：`src/main.tex` 第 75–84 行
- **问题**：摘要描述了系统架构和功能，但未包含具体的验证数据（如"能量漂移 < 0.5%"、"小角度偏差 < 2%"）。
- **建议**：在摘要末尾添加一句量化成果："物理验证结果表明，系统能量漂移控制在 0.38% 以内，小角度线性化偏差低于 0.8%，单摆退化周期偏差低于 0.05%。"

### P2-3. `\graphicspath` 含上级目录引用

- **位置**：`src/main.tex` 第 48 行
- **问题**：`\graphicspath{{../figures/output/}}` 使用了 `../` 上级路径。这在当前 `build.py` 工作流中正确，但如果用户手动进入 `src/` 编译会失败。虽非竞赛扣分项，但降低了源码的可移植性。
- **建议**：在注释中说明此路径依赖 `build.py` 的工作目录约定。

### P2-4. I01 截图已准备但未使用

- **位置**：`figures/output/I01_explore-mode-3d-main-scene.png`
- **问题**：已准备但未引用（与 P0-2 相关）。
- **建议**：见 P0-2。

### P2-5. 宏包 `subcaption` 已加载但未使用

- **位置**：`src/main.tex` 第 36 行
- **问题**：`\usepackage{subcaption}` 已加载但全文无 `subfigure` 环境。
- **建议**：如不计划使用子图，可移除以减少编译开销。

### P2-6. 目录页（TOC）占一整页
