## 五、发现的问题与风险（按严重程度）

### 🔴 严重 — 设计约束未落地

1. **故事模式集成完全缺失 (步骤 7/9)**
   - `GlobalNavBar` 未实现故事模式脉冲动画（`animate-pulse`）
   - `GlobalNavBar` 未在故事模式激活时禁用其余 Tab
   - `AppShell` / `setMode` 未阻止故事模式中的键盘快捷键切换
   - 未监听 STY-01 的 `storyEnd` 事件自动退出故事模式
   - **影响**：故事模式演示中用户误触键盘切换会打断演示，评审体验受损

2. **App.tsx 仅传入 ExplorePage**
   - `AppShell` 依赖 `children` 按 explore/analyze/lab/story 顺序排列
   - 当前仅传入 1 个 `<ExplorePage />`，其余 3 个位置为 `undefined`
   - 切换到 analyze/lab/story 模式时内容区显示 "模式「xxx」— 待实现" 占位文字
   - **影响**：虽然不会崩溃（fallback 机制正常），但功能不完整

### 🟡 中等 — 功能不完整

3. **快速切换防抖缺失 (异常 2)**
   - 规格要求 300ms 防抖窗口，当前依赖 React 18 自动批处理
   - 无显式 debounce/throttle 机制
   - **影响**：仅在极端快速切换（手动编程触发）时可能产生多余渲染

4. **Children 索引映射脆弱**
   - `AppShell.tsx:48-52` 用 `Array.from({length:4}, ...)` + `MODE_REGISTRY.forEach` 索引对齐
   - 规格推荐了具名插槽方案（`<AppShell explore={...} analyze={...} />`）但未采用
   - **影响**：`App.tsx` 传子节点顺序错误时会导致模式内容错位

5. **组件测试缺失**
   - 无 `GlobalNavBar` / `AppShell` / `ModeErrorBoundary` 的组件级测试
   - `appStore.test.ts` 仅覆盖 store 层（13 tests），不覆盖 UI 渲染和用户交互
   - **影响**：UI 回归无法自动化发现

### 🟢 轻微 — 改进建议

6. **PWA safe-area 兜底值为 0px**
   - `AppShell.tsx:98`: `env(safe-area-inset-bottom, 0px)` → 规格建议兜底 20px
   - **影响**：PWA 添加到主屏幕时底部导航栏可能与 Home Indicator 重叠

7. **无 layout 目录 barrel export**
   - `src/shared/components/layout/` 下 3 个组件各自独立导出，无 `index.ts` 统一出口
